# MongoDB Atlas Free Tier — Setup Guide

Everything needed to get this project talking to Atlas, plus the exact `.env`
contents. Roughly 10 minutes.

**Two things have changed recently that make older tutorials misleading:**

* The free tier is now labelled **"Free"** in the Atlas UI, not "M0". It is the
  same thing — the docs renamed it to match the interface.
* As of **22 January 2026**, the M2, M5, and Serverless tiers no longer exist.
  They were migrated to Flex clusters. Screenshots showing "M2 / M5 / Shared"
  options are out of date.

---

## 1. Create the account and cluster

1. Go to <https://cloud.mongodb.com> and sign up (email, Google, or GitHub).
   Verify your email; no credit card is required.
2. Create a project — name it something like `coc-knowledge-base`. **One free
   cluster is allowed per project**, so give this project its own.
3. Click **Create** / **Build a Database**.
4. Choose the **Free** tier.
5. Pick a **cloud provider and region closest to you**. All three providers
   support the free tier. Region affects latency on every query, and you cannot
   move a cluster later without recreating it — worth thirty seconds of thought.
6. Name the cluster (`Cluster0` is fine) and create it.

Provisioning takes 1–3 minutes.

> If Atlas offers to "Automate security setup", you can accept it — it walks you
> through the next two steps. Doing them manually is clearer, and that is what
> follows.

---

## 2. Create a database user

**Security → Database Access → Add New Database User.**

* Authentication method: **Password**
* Username: e.g. `coc_app`
* Password: use **Autogenerate Secure Password** and copy it immediately — it
  cannot be viewed again
* Role: **Read and write to any database**

> **Avoid special characters if you set the password yourself.** Anything in
> ``@ : / ? # [ ] %`` must be percent-encoded in the connection string, and a
> raw `@` in a password is the single most common cause of "authentication
> failed" when the credentials are actually correct. An autogenerated password
> is URL-safe. If you must use one with symbols, encode it:
>
> ```python
> from urllib.parse import quote_plus
> quote_plus("p@ss:w0rd/")     # 'p%40ss%3Aw0rd%2F'
> ```

This user is separate from your Atlas login. It exists only to connect to the
database.

---

## 3. Allow network access

**Security → Network Access → Add IP Address.**

* Development on your own machine: **Add Current IP Address**
* Behind a corporate VPN, or on a laptop that moves: your egress IP will change
  and connections will start timing out. Either re-add the new IP each time, or
  ask your network team for the fixed egress CIDR and add that.
* `0.0.0.0/0` (allow from anywhere) works and is convenient for a first test, but
  do not leave it in place — with a leaked URI it is the whole database. If you
  use it to get unblocked, set an expiry when you add it.

A connection that hangs and then times out is almost always this step, not
credentials.

---

## 4. Get the connection string

Click **Connect** on the cluster → **Drivers** → **Python**, version 3.12 or
later. Copy the string. It looks like:

```
mongodb+srv://coc_app:<db_password>@cluster0.ab1cd.mongodb.net/?retryWrites=true&w=majority&appName=Cluster0
```

Replace `<db_password>` — including the angle brackets — with the password from
step 2.

You do **not** need to add a database name to the URI. This application takes the
database and collection names from separate settings, so anything in the URI path
is ignored.

---

## 5. Fill in `.env`

Copy `.env.example` to `.env` in the project root and set the following. These
are the exact names `coc/config.py` reads.

```bash
# ---- MongoDB Atlas (required) ------------------------------------------
MONGODB_URI=mongodb+srv://coc_app:YOUR_PASSWORD@cluster0.ab1cd.mongodb.net/?retryWrites=true&w=majority
MONGODB_DB=coc_rag
MONGODB_COLLECTION=coc_chunks
VECTOR_INDEX_NAME=coc_vector_index
TEXT_INDEX_NAME=coc_text_index

# ---- Embeddings (required: pick one provider) --------------------------
EMBED_PROVIDER=voyage                 # voyage | openai | local
EMBED_MODEL=voyage-3.5
EMBED_DIM=1024
VOYAGE_API_KEY=pa-...                 # required when EMBED_PROVIDER=voyage
OPENAI_API_KEY=                       # required when EMBED_PROVIDER=openai

# ---- Answer generation (required for Phase 3) --------------------------
ANSWER_PROVIDER=anthropic             # anthropic | openai
ANSWER_MODEL=claude-sonnet-4-6
ANTHROPIC_API_KEY=sk-ant-...

# ---- Optional ----------------------------------------------------------
WORK_DIR=./data
# TIKTOKEN_CACHE_DIR=/opt/tiktoken_cache   # only if BPE files are pre-downloaded
```

### What each one does

| Variable | Required | Notes |
|---|---|---|
| `MONGODB_URI` | yes | Password must be URL-encoded if it contains symbols |
| `MONGODB_DB` | yes | Created automatically on first write |
| `MONGODB_COLLECTION` | yes | Holds the chunks. `coc_documents` and `coc_query_log` are derived from defaults in code |
| `VECTOR_INDEX_NAME` | yes | Must match the index you create in step 6 |
| `TEXT_INDEX_NAME` | only for hybrid search | Costs one of your three search indexes |
| `EMBED_PROVIDER` / `EMBED_MODEL` | yes | `voyage-3.5` is the tested default |
| `EMBED_DIM` | yes | **Must equal `numDimensions` in the vector index.** A mismatch produces an index that silently returns nothing |
| `VOYAGE_API_KEY` | if using Voyage | From <https://dash.voyageai.com> |
| `OPENAI_API_KEY` | if using OpenAI | For embeddings and/or answers |
| `ANTHROPIC_API_KEY` | if answering with Claude | From <https://console.anthropic.com> |

**Add `.env` to `.gitignore`.** It holds a database password and API keys.

## 6. Create the vector search index

Phase 2 creates it for you via `pymongo`, and index creation through drivers is
supported on free clusters. If you would rather create it by hand:

**Atlas UI → your cluster → Atlas Search → Create Search Index → JSON Editor**,
targeting `coc_rag.coc_chunks`:

```json
{
  "fields": [
    { "type": "vector", "path": "embedding", "numDimensions": 1024, "similarity": "cosine" },
    { "type": "filter", "path": "doc_id" },
    { "type": "filter", "path": "plan_id" },
    { "type": "filter", "path": "plan_year" },
    { "type": "filter", "path": "type" },
    { "type": "filter", "path": "section_path" },
    { "type": "filter", "path": "page_start" },
    { "type": "filter", "path": "needs_review" }
  ]
}
```

Name it to match `VECTOR_INDEX_NAME`, and select index type **Vector Search**
(not the default Search).

Builds take a minute or two. **Queries return nothing until the index is
queryable** — that is the most common "it's broken" moment, and it isn't broken.

> Note: `mongosh` cannot create or manage search indexes on free clusters. Use
> the UI or the driver (which is what this application does).

## 7. Test the connection

From the project root:

```bash
python -c "
from coc.config import load_settings
from coc.vectorstore import get_collection, list_search_indexes
s = load_settings()
c = get_collection(s.mongodb_uri, s.mongodb_db, s.mongodb_collection)
print('connected; documents:', c.estimated_document_count())
for i in list_search_indexes(c):
    print(' index:', i.get('name'), i.get('type'), i.get('status'), 'queryable:', i.get('queryable'))
"
```

Or use the **Test MongoDB connection** button on the app's home page, which
prints the same information.

## Free tier limits to design around

| Limit | Value | Impact here |
|---|---|---|
| Storage | 512 MB | A 185-page COC needs ~2.7 MB at 1024 dims. Room for well over 100 documents |
| Operations | ~100/sec | Writes are batched at 100 with a throttle; leave it at 0.4s |
| Connections | 500 | Not a constraint for this app |
| Search indexes | 3 | Vector index is required; the lexical index for hybrid search costs a second |
| Sort memory | 32 MB | Not a constraint — pipelines here are short |
| Free clusters | 1 per project | Create a second project if you need another |
| Vector dimensions | ≤ 4096 | 1024 is the default here |

Free clusters never expire and no credit card is required.

**On cost control:** embedding is a one-time cost per document (~122K tokens for
the 185-page SPD). Query-time cost is one embedding call per question plus the
answer model. Nothing about the database itself costs money at this tier.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Hangs, then `ServerSelectionTimeoutError` | IP not allow-listed | Network Access → add your current IP |
| `Authentication failed` with correct password | Unencoded symbol in the password | URL-encode it, or regenerate a URL-safe one |
| `Authentication failed`, credentials look right | Using your Atlas login instead of the database user | Create a database user in step 2 |
| Search returns `[]`, no error | Index still building, or `EMBED_DIM` ≠ `numDimensions` | Check `queryable` status; confirm the dimensions match |
| `Index not found` | `VECTOR_INDEX_NAME` differs from the index name | Make them match exactly — case-sensitive |
| Writes slow or throttled | 100 ops/sec ceiling | Keep the write throttle at 0.4s |
| `dnspython` / SRV resolution error | Missing dependency or blocked DNS | `pip install "pymongo[srv]"`; corporate DNS may block SRV lookups |

## Security notes

* `.env` is not encrypted. Keep it out of version control and off shared drives.
* Use a dedicated database user per environment, not one shared credential.
* Remove `0.0.0.0/0` from the access list once you are past first setup.
* Rotate the database password if the URI is ever pasted into a ticket, chat, or
  screenshot.
* A COC is plan-level and normally free of member PII, but if you ever index a
  document containing member data, the free tier is not the right place for it —
  it lacks the backup, audit, and access controls that would apply.
